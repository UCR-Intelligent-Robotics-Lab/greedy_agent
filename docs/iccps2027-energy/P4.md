## Registered designs and scope

`homogeneous_v1` expands to one per agent. `hetero_2x1p5_v1` is exactly
`(1.0, 1.0, 1.5, 1.5)` for four agents. Its classification is
"design choice; heterogeneous hardware profile lambda^i; not measured".
Registry records are immutable. IDs, agent counts, lengths, finite values and
strict positivity are validated. Arbitrary agent.energy_param scales remain
forbidden: it must still equal 1. Lambda is applied once inside the P1 adapter,
using the stable agent index. Homogeneous calls execute the original P1 lookup
without an extra multiplication. Scope exit restores the class and context.

`run_single.py --hardware_profile` defaults to `homogeneous_v1`. Explicit use
requires non-legacy costs, including explicit homogeneous. Legacy runs gain no
hardware config or provenance fields. Non-legacy runs record the registered
snapshot and `hardware_profile_lambda` in config and provenance. The existing
P2 evaluation manifest already captures the complete config and needs no edit.

## Offline accounting

`summarize_energy_profiles.py --runs ... --out FRESH_DIRECTORY` automatically
writes `hardware_seed_metrics.csv` and `inputs.json` when input configs contain
hardware lambda. Each row represents one seed and evaluation table. The JSON
per-agent cost vector preserves stable index order. Mean and worst-agent costs,
step and support components are lambda-weighted. There are no seed averages,
intervals, or pooled-across-seed support shares in this hardware output.

`--evaluation_hardware_profile hetero_2x1p5_v1` scores saved LIO or homogeneous
REFiNE trajectories under heterogeneous hardware without modifying their policy,
training provenance, or raw episode files. Both training and evaluation hardware
identities are recorded, including evaluation design provenance and input hashes.

Support share is lowest-lambda agents' lever count divided by all lever counts
within the seed. Agents 0 and 1 are lowest for the heterogeneous design; random
assignment reference is 2/4 = 0.5. No lever actions gives an empty value. Fully
homogeneous hardware has no lower-lambda group and also gives an empty value,
with an explicit status; its reference is undefined, not 0.5.

For pre-P4 inputs, missing lambda is accepted only with a clean recorded commit
from the explicit P1-P3b allowlist in energy_hardware_summary.py. Those source
revisions enforced energy_param=1 in the fixed-cost adapter. The reader prints
"homogeneous by construction" with that exact commit and records this inference
in inputs.json. Unknown/missing commits, dirty historical trees, inconsistent
metadata, and missing provenance are refused. This does not infer source from a
timestamp. Historical homogeneous summaries without evaluation override retain
the P2 CSV schemas; only the explicit origin record is added to inputs.json.
The synthetic P2 test fixture now declares its synthetic homogeneous source era;
no existing assertion is removed or weakened.

## Console-path correction

Runner and launcher now share `default_console_dir(manifest)`, derived from the
parent directory of the run targets. Thus a wave-1 formal manifest uses
`<campaign>_console`, smoke uses `<campaign>_smoke_console`, and wave 2 uses its
distinct results-root name. Existing consoles are never moved or deleted.
Previously produced P3b smoke consoles still occupy their old paths; this fix
does not remove that existing obstruction for a same-name formal launch.
