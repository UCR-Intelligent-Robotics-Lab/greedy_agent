## Purpose and mechanism

This baseline answers RTAS R7 and SenSys S1: does it matter that REFiNE places
energy in the policy objective rather than in the tradable environment reward?
The host is LIO. The intended difference from the matched REFiNE arm is where
energy enters, with the same task, cost table, hardware profile and imported beta.

LIO buffer reward enters incentive learning through the inner simulated update
at `lio/alg/lio_agent_er.py:393` and the outer J_inc returns at `:427-439`.
REFiNE feeds zero energy in incentive training at `lio/alg/REFiNE_er.py:402-405`.
This propagation difference is part of the design under test, not a confound to
remove. No incentive-update formula is changed by this implementation.

The source gate confirms `train_lio_er.py:346-354` writes agent i's cost to
buffer i and `:389-390` accumulates it in that buffer's total_energy. The P4
adapter already multiplies by that agent's lambda (P4 source
`sensys_runs/energy_profile_runtime.py:50-51`). Therefore lambda is not multiplied
again. The wrapper subtracts beta E_i/T from every reward in the returned buffer
in place. Beta comes from `config_room_REFiNE.get_config().lio.energy_weight`,
loaded through the existing TensorFlow-free config loader, never a copied value.

Both ordinary and prime calls (`train_lio_er.py:193-194` and `:212-213`) return
shaped buffers before the actor or incentive update. A scoped rebind of
`train_lio_er.run_episode` is restored in finally, including exceptions. Empty
buffers or invalid energy are rejected; nested scopes are refused to avoid
double charging. env.step is never wrapped. Periodic evaluation and the final
evaluation at `train_lio_er.py:280-283` remain unchanged; the P2 observer records
raw environment return. These training-file line numbers remain unchanged.

## Launcher and provenance

`run_single.py --energy_in_reward` is off by default and only accepts clean
`lio_er` with a non-legacy cost profile. Any registered hardware profile is
supported. Enabled runs record these fields in both config and provenance:

- `energy_in_reward: true`
- `energy_reward_beta`: the imported REFiNE value
- `energy_reward_form: episode_mean`

Disabled runs gain none of these fields and retain the original dispatch.
The LIO baseline has fairness multiplier zero. No training, environment,
agent, evaluator, config-factory, or optimizer file is edited.

## Summaries and pairing

`summarize_energy_profiles.py --runs ... --out FRESH_DIRECTORY` reads each
run's config. Its `objective` column is `energy_reward` for enabled runs and
`env_reward` otherwise, including old runs with no flag. The column is appended
in seed_metrics.csv, summary.csv and paired_differences.csv; paired rows also
identify reference_objective. Hardware identities are explicit. Lambda-weighted
costs and the P4 seed-level hardware file remain available. summary.csv contains
seed means, paired differences remain per seed, and no intervals are computed.

Energy-reward arms pair with env-reward references under the same evaluation
cost table, evaluation hardware and identical complete seed sets. Only reference
arms with method `lio_er` and objective `env_reward` ignore their training cost
and hardware profiles: these affect accounting only. LIO's update does not read
buffer energy (`lio/alg/lio_agent_er.py:339-373`), and fixed cost and lambda
lookups consume no RNG (`sensys_runs/energy_profile_runtime.py:48-52`;
`sensys_runs/energy_hardware_runtime.py:32-37`). Thus wave-1 LIO uniform_v1
inputs are valid references for paper_ratio energy-reward arms, including
heterogeneous comparisons using P4 evaluation-only hardware rescoring. Original
training identities remain recorded. `inputs.json` records this rule and its
source justification; affected paired rows carry
`reference_training_match=lio_env_reward_accounting_only` and the justification.
No REFiNE or energy-reward arm receives this exemption: energy-reward comparisons
against REFiNE require matching training cost and hardware profiles. Seed-set
disagreement is an error; genuinely missing references produce PAIR_MISSING.
Existing P2 comparisons among environment-reward controls remain available.

## What is not claimed

This change supplies a baseline, not evidence of a learning advantage. It does
not isolate only the outer J_inc edge: energy enters both incentive-learning
paths by design. It does not change raw task rewards in evaluation, fit beta,
measure hardware Joules, add fairness shaping, or establish checkpoint byte
identity. Costs remain normalized modeled quantities. No trained results or
Nano validation are produced by this Windows change set.

test both rollouts and every agent, check nonzero-energy subtraction and scope
restoration, compare raw P2 sidecars, verify provenance and pairing, and compare
wave-1/wave-2 manifests against P4. Target-platform TensorFlow checks remain
