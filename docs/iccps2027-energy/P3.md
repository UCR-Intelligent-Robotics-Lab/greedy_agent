## Fixed experiment list

The minimal energy plan, Section 6, specifies ER(4,2), the existing ten seed
indices 1 through 10, and these four arms:

1. LIO with `uniform_v1` for accounting only.
2. REFiNE with `uniform_v1`, fairness multiplier zero.
3. REFiNE with `low_contrast_v1`, fairness multiplier zero.
4. REFiNE with `paper_ratio_v1`, fairness multiplier zero.

Seeds come from `run_batch._seed`, currently 12341 through 12350. There are
40 training runs. LIO is trained once per seed, not once per accounting profile.
Every final trajectory is later scored under all three tables by the P2 summary.

Config factories supply training episodes (currently 25000), period (500),
periodic evaluation count (10), final evaluation count (100), networks, discount,
exploration and REFiNE energy weight (currently 1.0). P3 imports these values.
It explicitly passes the zero fairness multiplier and the imported energy weight.
No beta search, EIA arm, extra task or checkpoint-selection rule is introduced.

Each run has its own fresh output directory:

```text
lio/results/<campaign>/<method>_<training_profile>_s<seed>/
```

The JSON manifest contains executable argv, host-quoted command text, full effective
config including profile provenance, output directory, exact final checkpoint prefix,
training episode, platform, thread/GPU settings, generator interpreter and source hashes.
The reported git state is the state at generation, not a claim of a clean committed run.
Generate the final manifest on the actual execution host with its intended interpreter.

Direct config-file loading avoids `lio.alg.__init__` and TensorFlow during dry run;
it executes the original config factory without copying its constants. Command
construction reuses `run_batch.spec_to_argv` and adds the P1 cost-profile flag.

## Review commands (no training)

On the Nano, activate the established environment first and use its interpreter:

```bash
conda activate LIO_tecs
python -m sensys_runs.energy_profile_campaign --platform nano --threads 2 --dry-run
python -m sensys_runs.energy_profile_campaign --platform nano --threads 2 --smoke --dry-run --format commands
```

For a local host, use `--platform local` and the intended local Python environment.
Commands use PowerShell quoting on Windows and POSIX quoting on Linux. A Nano label
alone does not turn local execution into Nano execution or into a robot measurement.

To save review artifacts on Linux without executing any generated command:

```bash
python -m sensys_runs.energy_profile_campaign --platform nano --threads 2 --out /tmp/iccps-energy-manifest.json
python -m sensys_runs.energy_profile_campaign --platform nano --threads 2 --smoke --format commands --out /tmp/iccps-energy-smoke.commands
```

The files must be absent. `--dry-run` and `--out` cannot be combined. Manifest
files cannot be placed under `lio/results`. All runs are validated before any
manifest/command output. There is no resume: an existing target invalidates the
matrix. Use a new, reviewed `--campaign` name when a new campaign is needed.


Before scientific launch, Yifan must complete the real TensorFlow tests, the
original-versus-extended short-run regression, and one short smoke per arm in the
execution environment. Smoke uses the existing batch runner's short duration and
period, but preserves the campaign's periodic/final evaluation counts. It writes
to `<campaign>_smoke`, separate from the formal runs. Smoke verifies execution,
sidecars and output refusal; it does not establish learning quality.

Launch only from the reviewed commit/tag, in the established SSH/tmux environment.
Review the generated commands before executing them manually. Do not use the old
all-method batch launcher for this panel: its matrix is a different experiment.
